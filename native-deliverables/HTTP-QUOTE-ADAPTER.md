# Synchronous quote adapter — implemented locally, installation unbound

`POST /api/acquisitions/quote` is the new route. It composes the approved observed-data valuation, house repair/70% formula and exact offer/counter rules. It does not call `/api/acquisitions/comps` or its older estimated-price rejection policy. The old comps/proposals routes and deployed disabled API are unchanged.

The concrete `createGhlNativeQuoteRuntime` reads GHL custom-object records, Contact holds and relations through an injected authorized HTTP transport; creates one immutable quote decision; reads it back; and revalidates native state. Tests exercise the complete Request → real adapter → simulated GHL HTTP server → native-shaped records → receipt → Response path. This is local synthetic acceptance, not an installed native integration or spoken-call proof.

## Native reads and smallest write sequence

1. Resolve the protected call Context by a hash of tenant, actor, call, seller, exact Property and Analysis/version. Read the unique match directly. Native context includes the sanitized observed pair and referenced discovery facts; it cannot come from HTTP input.
2. Read its Policy and Offer records independently. Validate tenant/actor, native policy ID, explicit comp adoption, current authority, exact terms and repair policy. Nothing in the adapter activates the proposed 1 mile / 365 days / ±30% / minimum 3 / 24 hour settings.
3. Read Property and Analysis by exact native IDs; project only the actual supplied field keys. Exhaust the Evidence search, reject incomplete/repeated/changing pages, and validate full exact evidence replay. Check Contact global/voice DND, explicit takeover value, seller↔Property relation, Analysis↔Property relation and complete Evidence↔Analysis relations. Unknown hold values fail closed.
4. Compute the candidate and a digest of actual persisted state. Re-read and recompute before recording. A unique quote key hashes tenant, actor and request ID; changes to the same request's decision conflict.
5. Search that key. If absent, create exactly one immutable native quote record containing key and decision JSON. Do not update a Property pointer, approval counter, Offer, contact, agreement or delivery state. If create fails or its response is lost, search/read the same key; absent readback returns `IN_PROGRESS`, with no second create in that attempt. A later retry uses the same unique key.
6. Compare the complete persisted decision, re-read all authoritative inputs again, and return its native record ID only if they still agree. Fresh STOP/revocation/terms or pointer changes prevent output even when a quote audit record already exists. Replay repeats these checks after process/adapter recreation.

**Consistency limit:** uniqueness is single-record duplicate control. The API calls above are sequential, not a transaction, reservation, compare-and-swap, exactly-once speech or revocation barrier. State can change after the last read and before/during Jessica's speech. An immutable recorded decision is an audit artifact, not unconditional ongoing approval. Concurrent native writers and voice STOP handling require live acceptance; do not label this atomic. The adapter never sends a message, speaks, signs, consumes single-use authority or changes contract lifecycle.

## Documented API contract

The adapter uses the documented [Get Record](https://marketplace.gohighlevel.com/docs/ghl/objects/get-record-by-id/), [Create Record](https://marketplace.gohighlevel.com/docs/ghl/objects/create-object-record/) and [Search Records](https://marketplace.gohighlevel.com/docs/ghl/objects/search-object-records/) endpoints. Create sends `{locationId, properties}`; search sends location, page, page limit, field query and searchAfter, then checks record count and IDs. It uses the [Contact endpoint](https://marketplace.gohighlevel.com/docs/ghl/contacts/get-contact/) and [relation endpoint](https://marketplace.gohighlevel.com/docs/ghl/associations/get-relations-by-record-id/). Current docs show `Version: v3`; the transport uses that header on the fixed documented API origin with no added version path prefix. Contact extra fields and the relation list envelope are supplied via verified binding paths because the published examples are incomplete. No guessed response envelope is activated.
